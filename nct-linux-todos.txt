		-- System and OS Profile - Everything about the system itself, its host hardware, its root
		directory listing and sizes. Lists what the root directories mean and lists them in a table 
		with descriptions.
		
		Here are all the top-level directories in a Debian Linux system:
					
					On UNIX, everything is treated as a file in the browsable
					file system, e.g. a hardware device is represented as a file in /dev,
					
					| Directory | Purpose |
					|---|---|---|
					| Root | `/` | The root of the entire filesystem; contains everything |
					| Essential Program Binaries | `/bin` | Essential user command binaries (e.g., `ls`, `cp`, `cat`). On Debian 12+ this is a **symlink to `/usr/bin`** |
					| Boot Loading | `/boot` | Static files for the boot loader: kernel images, initrd, GRUB config |
					| Devices | `/dev` | Device files representing hardware (disks, terminals, `null`, etc.) |
					| Configuration Files | `/etc` | Host-specific system configuration files (network, users, services, `fstab`, etc.) |
					| User Home Directories | `/home` | Personal home directories for regular users (e.g., `/home/alice`) |
					| Libraries | `/lib` | Essential shared libraries and kernel modules. On Debian 12+ this is a **symlink to `/usr/lib`** |
					| Storage Media Drives | `/media` | Mount points for automatically mounted removable media (USB drives, CD-ROMs) |
					| Manual Mount Point | `/mnt` | Temporary mount point for manually mounting a filesystem |
					| Optional Add-On Software | `/opt` | Add-on / optional application software packages (self-contained, not part of core system) |
					| Process Information | `/proc` | Virtual filesystem exposing real-time process and kernel info (e.g., `/proc/cpuinfo`, `/proc/meminfo`) |
					| Superuser Home | `/root` | Home directory for the root (superuser) account |
					| Runtime Data | `/run` | Volatile runtime data (PID files, sockets, locks); backed by tmpfs, cleared on reboot |
					| System Administration Binaries | `/sbin` | Essential system administration binaries (e.g., `fsck`, `reboot`). On Debian 12+ this is a **symlink to `/usr/sbin`** |
					| Service Data | `/srv` | Data served by the system to other machines (web content, FTP, etc.) |
					| Kernel Device Model | `/sys` | Virtual filesystem exposing kernel device model and hardware info (e.g., `/sys/class/net/`) |
					| Temporary Files | `/tmp` | Temporary files; typically cleared on reboot |
					| Secondary Hierarchy | `/usr` | The bulk of user programs, libraries, and documentation. Key subdirs: `/usr/bin`, `/usr/sbin`, `/usr/lib`, `/usr/share`, `/usr/local` (for manually compiled software) |
					| Variable Data | `/var` | Variable data that changes at runtime: logs (`/var/log`), spool (`/var/spool`), caches (`/var/cache`), persistent state (`/var/lib`), durable temp files (`/var/tmp`) |
					| Recovered Files | `/lost+found` | Holds recovered orphaned files after a filesystem crash (ext* filesystems only) |
					
					> **Note:** On Debian 12 (Bookworm) and later, the **usr-merge** change means `
					/bin`, `/sbin`, and `/lib` are symlinks into their `/usr/` counterparts, so the 
					actual binaries and libraries live under `/usr`.

nct modules.

important note is that modules can be marked as
available to shell scripts, so that shell scripts come
with a lot of functionality.  

it looks as though as we build this, there is blending
of the conventional services and app kit.  in fact it
may be an exposure that this should be this way
since when people use the command line they
often have to install functionality that is already
inside the local dev app kit but requires compilation
for those apps to use it.  e.g. shell scripts can't
make use of any .framework files in Mac OS.
Furthermore, an AI agent built into the system
will have access to these utilities and won't
have to install equivalent functionality from
packages when carrying out tasks.
e.g. Any app can get access to map and geo services.
