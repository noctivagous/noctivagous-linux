# Research

Sourced research behind design decisions for Noctivagous-Linux. Each topic
keeps its full report, its source notes, and — where one was made — the
reading page built from the report (`page.html`, standalone: open it in a
browser).

| Directory | Topic | Date |
|---|---|---|
| `linux-daily-driver-blockers/` | What prevents people using Linux as a daily driver — first-person trials and challenge videos: one hard blocker (proprietary apps, kernel anti-cheat, work/school lock-in, laptop hardware) plus a pile-up of small friction. | 2026-11-25 |
| `linux-de-system-interface/` | How a desktop environment should reflect the Linux system underneath — systemd/journal/D-Bus interfaces, GNOME/KDE/Xfce mapping, floating problems up as issues, emergency/repair tools, driver and laptop frictions. Basis for the system-interface and recovery proposals in the desktop planning. | 2026-11-26 |
| `diy-self-hosting-audience/` | The DIY / self-hosting audience (Hackaday, XDA): who they are, what they host at home and with what stack, their operational frictions, precedents (YunoHost, CasaOS, Umbrel, Proxmox, Cockpit…), and design implications — Host as a value of Computer Use Mode, a Compose-native Services Centre, LAN-only by default with an explicit ask before internet exposure. | 2026-11-26 |

Notes on the evidence: the reports carry their own caveats inline. Survey
figures are from self-selected community samples; where a number comes from
secondary analysis rather than the primary source, the report says so.
